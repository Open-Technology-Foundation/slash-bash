### [WARN] BCS0305 — Printf Format Strings (Tier: recommended)

**Lines 143, 150**

Both `__msg` and `_vecho` embed variable expansions directly in double-quoted format strings, violating the rule that format strings use single quotes while variables are passed as separate arguments.

```bash
# Line 143 — current (VIOLATION)
__msg() { >&2 printf "${_SB_AGENT:-${SCRIPT_NAME:-slash-bash}}: $1 %s\n" "${@:2}"; }

# Line 150 — current (VIOLATION)
_vecho() { ((_VERBOSE)) || return 0; >&2 printf "${_SB_AGENT:-${SCRIPT_NAME:-slash-bash}}: %s\n" "$@"; }
```

The `#shellcheck disable=SC2059` on line 140 suppresses shellcheck's warning but does not constitute a BCS suppression (`#bcscheck disable=BCS0305`).

**Fix:**
```bash
# Line 143
__msg() { >&2 printf '%s: %s %s\n' "${_SB_AGENT:-${SCRIPT_NAME:-slash-bash}}" "$1" "${@:2}"; }

# Line 150
_vecho() { ((_VERBOSE)) || return 0; >&2 printf '%s: %s\n' "${_SB_AGENT:-${SCRIPT_NAME:-slash-bash}}" "$@"; }
```

### [WARN] BCS0606 — `&&` Chain Without `||:` in Global Scope (Tier: core)

**Line 579**

```bash
shopt -q nullglob && _sb_was_nullglob=1
```

When `nullglob` is **not** set, `shopt -q nullglob` returns exit code 1. The `&&` short-circuits, leaving the compound expression with exit code 1. If the library is ever sourced into a shell with `set -e` active (e.g., a user who has `set -e` in their `.bashrc` before sourcing this library), this silently exits the shell at this line.

The interactive guard at line 24 (`[[ $- == *i* ]] || return 0`) mitigates this in practice — interactive shells rarely have `set -e` — but the idiomatic BCS fix is unconditional:

```bash
# Current (VIOLATION)
shopt -q nullglob && _sb_was_nullglob=1

# Fix
shopt -q nullglob && _sb_was_nullglob=1 ||:
```
