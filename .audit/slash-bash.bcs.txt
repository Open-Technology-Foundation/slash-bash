## BCS0606 — Conditional Declarations [ERROR] (core)

**Line 24:**
```bash
(($#)) && >&2 printf "$SCRIPT_NAME: %s\n" "$@"
```

`die()` is called with only an exit code (no message) in patterns like `die 0`. After `shift ||:` removes the exit code, `$#` becomes 0. `(($#))` then evaluates to 0 (false), returns exit code 1, and under `set -e` + `inherit_errexit` the script exits *before* reaching `exit "$ec"` on line 25.

**Fix — append `||:` (preferred):**
```bash
(($#)) && >&2 printf '%s: %s\n' "$SCRIPT_NAME" "$@" ||:
```
**Or — use inverted form (avoids the problem structurally):**
```bash
((!$#)) || >&2 printf '%s: %s\n' "$SCRIPT_NAME" "$@"
```
**Or — adopt BCS0602's canonical die() form:**
```bash
die() { (($# < 2)) || >&2 printf '%s: %s\n' "$SCRIPT_NAME" "${@:2}"; exit "${1:-0}"; }
```

`★ Insight ─────────────────────────────────────`
BCS0606 exists precisely because `((flag)) && action` looks like a safe guard, but under `set -e` the *compound expression* `((flag)) && action` still returns exit code 1 when the condition is false — and `set -e` sees that non-zero exit from the standalone statement. The `||:` drains the 1 without masking real failures downstream (since `:` always succeeds). The inverted `||` form is structurally safer because the right-hand side of `||` returns 0, so no `||:` is needed.
`─────────────────────────────────────────────────`

## BCS0305 — Printf Patterns [WARN] (recommended)

**Line 24:**
```bash
>&2 printf "$SCRIPT_NAME: %s\n" "$@"
```

BCS0305 mandates single-quoted format strings; embedded variables belong as arguments.

**Fix:**
```bash
>&2 printf '%s: %s\n' "$SCRIPT_NAME" "$@"
```

> **Note:** BCS0703's own canonical `_msg()` example uses the same double-quoted pattern (`printf "$SCRIPT_NAME: $1 %s\n"`), making this an internal BCS inconsistency. The practical risk here is low — `SCRIPT_NAME` is set via `realpath` and can't contain printf format specifiers — but the rule is clear.
