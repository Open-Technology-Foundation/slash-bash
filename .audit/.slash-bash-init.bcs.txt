**BCS0301 — Double Quotes on Static Strings**

`Tier: style → [WARN]`

**Lines 41, 43, 44, 45, 47** — Provisional PS1 block uses double quotes on strings with no shell variable expansions. In double quotes, neither `\e`, `\[`, `\033`, `\u`, `\h`, `\w`, `\n` nor `\\$` require double-quote processing — the resulting string is identical with single quotes (bash PS1 evaluator handles all `\x` prompt escapes itself).

```bash
PS1="\[\e]0;\u@\h: \w\a\]"           # line 41 — no $ vars
PS1+="\[\033[38;5;8m\]\$?:"          # line 42 — \$? → $? same as single-quote $?
PS1+="\[\033[00m\]\[\033[01;34m\]\w" # line 43
PS1+="\[\033[00m\]:\[\033[01;32m\]\u@\h" # line 44
PS1+="\[\033[00m\]\n\\$ "            # line 45 — \\$ → \$ same as single-quote \$
```
Fix: use single quotes on all lines (the second PS1 block at lines 70–76 already does this correctly):
```bash
PS1='\[\e]0;\u@\h: \w\a\]'
PS1+='\[\033[38;5;8m\]$?:'
# etc.
```

**BCS0706 — No Centralized Color Variables**

`Tier: recommended → [WARN]`

**Lines 41–47 and 70–76** — Both PS1 construction blocks embed ANSI escape codes inline with no centralized color variable declarations (no `declare -r RED=... NC=...` block). BCS0706 requires a single conditional block to define all color variables, with both branches declaring the same set:

```bash
if [[ -t 1 && -t 2 ]]; then
  declare -r ... BOLD=$'\033[1m' DIM=$'\033[2m' ITALIC=$'\033[3m' NC=$'\033[0m'
else
  declare -r ... BOLD='' DIM='' ITALIC='' NC=''
fi
```

The second PS1 block (final prompt) is also missing terminal detection — it unconditionally embeds color codes. If this file is ever sourced in a non-interactive context (piped init, log capture), color escapes leak into output.

Fix: declare named color variables with the standard conditional block, then reference them in both PS1 construction blocks.

`★ Insight ─────────────────────────────────────`
The `export` vs `declare -x` distinction (BCS0204) is more than cosmetic: `declare -x` makes the type and export intent explicit in one declaration, while bare `export` on an already-set variable is a two-step write that can silently export a variable before its value is finalized. For `BASH_COMPLETION_VERSINFO`, `declare -rx` also adds readonly protection against accidental override in child environments.
